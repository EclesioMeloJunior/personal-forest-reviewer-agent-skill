# Rust

- Bool parameters are a code smell. Name them (`let lookback = false`) or make them an enum: `self.latest_beacon_entry_for_epoch(epoch, Lookback::Enabled)`. A `bool` return nobody can read is a `Result`: "It's unclear to me what the return bool here denotes."
- `let mut x = A; if cond { x = B }` becomes `let x = if cond { B } else { A }`. `if cond { bail!() }` becomes `ensure!`; `match` + `return Err` becomes `bail!` or `.context("...")?`; "`match` (it's more idiomatic Rust than conditionals here)". Error mapping right before an `unwrap` is redundant.
- `.context(format!(..))` "will allocate a string **always** - you should prefer lazy evaluation via `.with_context`". In RPC handlers do not add context at all; `src/rpc/error.rs` overrides the message: "The error messages mustn't be modified." Typed `ServerError` over `anyhow` there: "define a new method on `ServerError`, e.g., `ServerError::unsupported_params`. It'd be cheaper." Never do expensive work to pick an error message.
- `out.to_vec()` on something that is already a `Vec` is a needless clone. `SmallVec` only if it propagates; otherwise "Let's just use `Vec` for now". Size for the common case. `TryFrom<&T>` that clones everything should consume: "normally we should just consume the original (compiler will tell)." Don't compute what you won't display.
- Smallest sufficient primitive: "Why do we need an atomic shared pointer here? Can we have a simple fat pointer `Box` instead?" "Why do we need `Arc<RwLock>` for i64? Wouldn't it be more efficient to use AtomicI64 instead?" "probably cheaper to use `starts_with`". No `as _`. `#[derive(Clone)]` on an Arc-backed type is ambiguous; use `inner: Arc<Inner>` or the `ShallowClone` convention: "A `Clone` subjectively implies an _independent copy_".
- Infallible means no `Result`; a sane default means no `Option`; a `Result` in a cache is wrong: "There should be a TokenAmount for every tipset, no?"
- Signatures stay small and typed: "Let's try not to bloat the function signature. Three parameters is already a stretch." Tuple outputs become a struct: "that's a pretty convoluted output. Let's have a dedicated struct?" Unsigned when it cannot be negative; `as` for lossless widening.
- Derive over hand-rolled: `strum::Display`, `Default`, `PartialEq` on API types ("a general good practice for the APIs is to have those derived"). `matches!` over downcast helpers, consistently across occurrences: "You extracted this one but do the downcast thing with others; why?" `Deref`/`DerefMut` on newtypes "to avoid always specifying `.0`". Constants are not built by parsing strings; hex is not built with `format!`. "Adding a zero is trivial."
- Redundant type annotations: "do you really need to put the type explicitly?" `let rounds = entries.iter().map(BeaconEntry::round).collect_vec();` with `itertools` in scope.
- Clever over clear: `izip!` is fine until `.enumerate()` does the job, "which everyone knows". `.gt` becomes `>`.
- Visibility as narrow as possible: `pub(in crate::beacon)` over `pub(crate)` over `pub`. "I think the visibility could be somehow limited?"
- Duplicate imports in test modules; `use super::*` already brings them. No helper for what an import solves.
- Repeated literal → a local: "you repeat `5` several times already; should be a constant (as in, just have `let test_rounds = 5;`)". Magic numbers in Rust get names too: "Why 3?" "why `2*20`? Why exactly 55th percentile?" But a module-level constant used once is the opposite smell: "what's the point of declaring a constant globally in a module and then using it in a single place?"
- Cryptopals rule, always: "Always operate on raw bytes, never on encoded strings. Only use hex and base64 for pretty-printing." Keep the typed value (hash, CID, key) until a string is actually required. Maintainers bring this up repeatedly; so should you.
- Type abuse: building a `Url` from `path.display().to_string()`, parsing JSON to produce test fixtures, assertions that are really a regex.
- Dead or never-running code: a `Drop` impl that realistically never fires, a `?` branch nothing reaches. Commented-out code: "Commented out code is a pretty bad smell ... If it later turns out to be needed, we can revive it" from git history. `#[allow(dead_code)]` per item with a reason or a `// TODO: This will be used in <PR link>`: "why is it needed?" "I'd mark individual items, not the entire file, then." Stale references: "that issue is closed, no?" "leftover".
- `unsafe` env mutation is a must-fix: "you must not do this, this is actually undefined behavior in concurrent environments."
- Pre-allocation when the size is knowable, as a nit: "Do we have a rough idea of the collection size ahead of time?" "We should know the total size to reserve upfront." But not a manual `reserve` before `extend`: "I checked `extend` impl and it will do the right thing without us manually checking."
- Naming that gives the reader a hint about which to use (`_legacy`/`_exact`, `_post_nv14`), not `_v3`; prescriptive names for work (`calc_encoded_len`, not `encoded_len`); full words ("what is `mcid`? `message_cid`? If so, let's use full name." "what's `ty`?"); no misleading `_` prefix on something used. Rename across the board, not in one place: "Ribasushi is a person. :)" → `data.riba.plus`; `FOREST_REGENERATE_GO_FFI` → `FOREST_F3_REGENERATE_GO_FFI`.
- Lotus parity prose is noise; divergence is signal: "Half of Forest code has stuff that's supposed to match Lotus. Should be pretty obvious." "it's definitely worth mentioning if we surprisingly don't follow it." A permalink on the value is enough. Translate concepts, not comments or error strings: "Let's not copy over Lotus comments as they are - if we're translating code from Go to Rust, we might as well translate some concepts." "Do we need to match the Lotus error? This would actually be a very confusing message for me."
