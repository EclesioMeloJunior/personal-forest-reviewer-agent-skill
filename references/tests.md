# Tests

- "do we have a failing case?" Every validation path needs the negative. A regression test must fail without the fix: "Test is not testing the fix." "This will happily pass without the fix." A synthetic unit test is not proof the check catches the real thing: "I'd like to confirm that the test fails when Forest reports bad metrics. A one off manual check would suffice."
- Propose the edge cases a maintainer would, as concrete cases: extra trailing entry, duplicate entry, null round plus extra entry, pre-upgrade network version, mainnet versus calibnet, activation boundary ("Is the activation boundary covered?"), input sizes 0, 1, 1024, the unknown-variant path. "Would these pass? If not, why?"
- Non-trivial logic without a test: "This seems untested and has some pretty non-trivial logic." Obvious code too: "let's add a simple test here. The code is kind of obvious but obvious things managed to bite us in the past." Bug fixes: "This bugfix should have associated tests."
- Tests `unwrap`, never `?`: "in case of a failure the exact line which failed won't propagate and will make things more difficult to debug. `unwrap` should be used there and the tests shouldn't return `Result`."
- Tests live in milliseconds. "`sleeps` in tests are suspicious. They make them slow and flaky (especially when run on shared CPUs). Can we make it more deterministic?" "Why 5s? How long are those tests taking? In general, we should aim for all tests to be in milliseconds land." Poll sub-second up to a timeout; don't shrink a timeout blindly ("are you sure 1 minute is enough and would not make the job flaky?").
- Flakiness is proven fixed, then the crutch goes: "Did you try running it, e.g., 100x times?" "If this mitigates the flakiness, then the `retries` should not be needed anymore." "Hm, stateful tests are failing. Is it related to the change?"
- `#[ignore]` is not a gate: "You should either use a feature flag or an environmental variable". Failing tests are ignored with tracking issues, never dropped from CI: "mark the failing ones as `ignored`, and have tracking issues for them. The currently passing ones should still be a part of CI."
- No tautologies: "I think it's fair to assume that field assignment in Rust works, and there's no need to test it." "you're essentially checking equality of the cid that you passed there." "What is this testing? We should trust that `Serialize` and `Deserialize` from `serde` work fine; no need to test our deps, especially on basic usage." Cover every category even trivially: "Let's add all supported categories of addresses to tests, `f0-f4`." A parity test needs a Lotus side: "Lotus doesn't have an implementation of the `trace_call` method. What would the comparison be against?" Gate time-dependent tests, don't comment them out: "we can just check if the current datetime is above XX." Don't repurpose an existing test for a new flag: "Now the test is missing the _non-default_ path. It should be a separate one."
- Don't assert on error strings: "Proper error types are for that." Large JSON expectations are `insta` snapshots. Byte-compat expected values go to snapshot files; other fixtures are hardcoded, not JSON parsed at runtime: "I'm lost on the need for JSON and parsing JSON here." Fixtures that claim to be recordings are sanity-checked: a chained mainnet entry without `previous_signature` "is this correct?" Snapshot fixture names carry actor and method.
- Tests read top-down: "These tests are unreadable. I appreciate the effort of making them concise, but at the very least there should be a comment telling what's happening and why." Parametrized cases → `rstest`, like elsewhere in the tree. Tests for a massive file go to a dedicated file: "Let's move it to a separate file, e.g., `state_tests.rs` as to not bloat this massive file any further."
- Shared global state in tests: "Is there a data race in this test?" Wallet tests single-threaded ("Wouldn't this introduce some nonce races?"); daemons cleaned up ("Does the daemon run still after the test? If so, what if there are two consecutive tests?").
- Tests must not reach public relays or the network. Brittle test wiring (env vars, global mutable config): "Surely we can do a more robust approach ... Do you have other ideas?" Pin the reference implementation you tested against: "Let's mark the exact version of `geth` you were testing against." Legacy shapes get a test: "we should test the legacy transactions have the field omitted."
- For a bug fix, ask why it was not caught: "the RPC parity tests should've eventually caught it. Perhaps we're missing some test cases there?" New RPC method checklist: `DESCRIPTION`, an entry in `src/tool/subcommands/api_cmd/test_snapshots_ignored.txt`, regenerated `insta` snapshots. Integration through devnet tests where the logic is end-to-end.
- Network upgrades: a passing migration on a 2k network with the Lotus stateroot ("Right now nothing exercises it."), "Where can I see the migration succeeding?", a fake run before release ("please make fake run as a sanity check"), every devnet variant updated ("seems you missed the `devnet-forest-miner`"), "Upgraded epoch seems wrong".
- Redundant checks: "Didn't you already assert the lengths match? In this case the `=self.epoch` shouldn't be needed, no?"
